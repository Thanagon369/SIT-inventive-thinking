# SIT - Systematic Inventive Thinking

A skill for generating ideas by *modifying what already exists* with five fixed operations, then finding a use for each result (Function Follows Form). Constraints are the engine: the goal is not more ideas, but ideas that are structurally different from the obvious ones.

Respond in the language the user writes in.

## Core principles

1. **Closed World.** Only use components that already exist in or immediately around the problem. Never "add a new gadget/AI/app/sensor". If a new element is needed, it must be borrowed from something already inside the boundary. The farther a resource is from the problem, the less inventive the solution tends to be.
2. **Function Follows Form.** Do not start from a problem. Start from the system, apply an operation to produce a new configuration (the "form"), then ask: who would want this, and what problem would it solve (the "function")?
3. **Break fixedness.** The operations deliberately attack two habits: *functional fixedness* (a part has only one job) and *structural fixedness* (the arrangement is the only possible one).
4. **Qualitative change (optional lens).** Look for configurations where the main negative factor is eliminated or reversed, not merely reduced.

## Workflow

Follow these steps in order. Do not skip step 1 or 2.

### 1. Frame the system and the Closed World
Ask (or infer from context) only what is missing:
- What is the product/service/process/system?
- Where is the boundary? What resources, people, data and environment count as "inside"?
If the user already gave enough, state your assumptions in one or two lines and continue. Ask at most one clarifying question.

### 2. Inventory
List the **components** (parts, steps, actors, resources) and the **attributes/variables** (things that can change: size, time, price, location, intensity, order, permissions...). Keep it to roughly 5-12 components. Show this list to the user.

### 3. Apply the five tools
Run each tool on the most relevant components. Start with **Subtraction** (it exposes fixedness fastest).

| Tool | Operation | Guiding question |
|---|---|---|
| **Subtraction** | Remove a component, ideally an essential one. | "What if this part did not exist? What replaces its job, using something already in the Closed World?" |
| **Task Unification** | Give an existing component an additional job. | "Which existing part could also do X, without adding anything new?" |
| **Multiplication** | Copy a component, but change the copy in a meaningful, even odd, way. | "What if there were two, and the second differed in size, place, time, or purpose?" |
| **Division** | Split a component or the whole, physically or functionally, and rearrange the pieces in space or time. | "What if this were separated and the pieces put somewhere unexpected, or in a different order?" |
| **Attribute Dependency** | Create a link between two variables that were independent, or break an existing link. | "What if A changed automatically when B changes?" |

For each generated variant, write the *new configuration* in one sentence before judging it.

### 4. Function Follows Form
For each variant, answer: **Who benefits? What problem does it solve? Why would they choose it?** If you cannot find a plausible beneficiary after a real attempt, discard it and say so briefly. Do not force a rationale.

### 5. Quality control (do this silently, then report only what passes)
Discard or rewrite a variant if it:
- introduces a new component from outside the Closed World,
- is simply the obvious/standard solution relabeled with a SIT tool name,
- duplicates another variant,
- cannot be explained in one sentence.
If a good idea already exists in the market, keep it but label it as "already exists" - that is useful evidence the pattern works.

### 6. Output
Present a table, then a short ranked shortlist:

| # | Component | Tool | New configuration | Beneficiary & function | Feasibility (low/med/high) | Main risk |
|---|---|---|---|---|---|---|

Then give the **top 3-5** ideas with one line each on what to validate first.
Aim for quality over volume: 10-20 solid variants are better than 60 weak ones.

### 7. Iterate
Offer to (a) re-run with a tighter or wider Closed World, (b) combine two tools on one component, or (c) go deeper on one idea. Changing the boundary changes the class of ideas produced.

## Honesty guidelines
- SIT is a *thinking aid*. It generates candidates; it does not validate them. Say so when presenting results, and leave viability, cost and market fit for the user to confirm.
- Do not claim guaranteed results. Evidence for creativity-training methods in general is moderate and mixed, and SIT-specific evidence is limited.
- Mark uncertain feasibility as uncertain rather than inventing numbers.
